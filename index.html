      What I built

      • The agentA stateful LangGraph workflow. It calls tools for customer-data retrieval, transaction analysis, document review, policy retrieval and onboarding actions, with schema validation, retries, persistent state, human-approval gates and an auditable history.
      • RetrievalHybrid indexes (BM25 plus semantic search, reranking, relevance thresholds, caching) over about 4,000 sections from up to 500 documents across three or four internal systems per deployment, and the pipeline that processes, chunks, embeds and refreshes them.
      • The evaluation gate120 representative banker and treasury questions, scored on relevance, grounding, source attribution, tool selection and structured-output compliance. It runs in CI/CD as the promotion gate to Kubernetes, ahead of expert sign-off.
      • ObservabilityLangfuse tracing of prompts, retrieved evidence, routing decisions, tool calls, latency, token usage and errors. I use production traces to reproduce the defects bankers report.
      • ControlsTyped, schema-validated tools over internal REST APIs, PostgreSQL, document stores and Salesforce, with scoped credentials, per-call audit logging and PII handling.
      • The services around itPython (FastAPI) and Java (Spring Boot) services, responses streamed to a React and Next.js client, Kafka consumers for core-banking events with idempotency and dead-letter handling, Temporal for long-running workflows, and Kubernetes promotion across dev, test and prod.

          Architecture

          Eight rules it is built around

          From the architecture doc. Many strategies may want a trade. Exactly one component may authorize one. The rest of the system exists to keep that true.

          1. One serialized authorizer.Mechanical, winners and LLM entries all pass through guardrails.check_order(). Nothing trades around it.
          2. Protection rests at the broker, not in the process that might die.Stop and target go in as a native OCA bracket with the entry, so they survive a crash.
          3. Risk sets size; size never sets risk.Quantity is allowed risk divided by the distance to the stop. If the stop is too far, the trade is skipped. The stop is never widened to make a trade fit.
          4. Every decision is journaled and replayable.Signals, vetoes, fills, exit polls and LLM calls go to an append-only log. 1,989 LLM calls are in it for Aug 12 to Sep 1, each with prompt hash, latency and cost.
          5. AI advises and may veto. It never sizes and never overrides a lock.The model proposes entries like any other worker, judges entries in shadow, and manages stops on open positions. API error, timeout, bad JSON, refusal: every failure degrades to pass.
          6. A restart adopts state. It never orphans a position.On boot, same-day positions are re-adopted, clamped to what the broker actually holds, and their brackets re-attached.
          7. Capture never blocks trading.A disk fault costs history, not an exit.
          8. New strategies ship dark.Off by default behind an environment flag, signal-only first.

          The same doc has a section called "Known structural debt". Its first line: the main runner file is about 5,200 lines and carries too many jobs. I would rather write that down than have you find it.

          The dashboard

          Trade Station, the console that runs it

          A React and Vite dashboard over a FastAPI back end, on my own domain, with updates pushed over a WebSocket. Three views (the trading desk, AI Trades and Performance) and a layout for the phone.

          • Trading deskWatchlist, live chart, order history and news, with the account figures: net liquidation, today's P&L, open P&L, cash and buying power.
          • Trade ticketManual orders, including limit and stop orders in pre-market, post-market and 24-hour sessions. Nothing is sent until you confirm it.
          • Kill switchIn the top bar on every view. Halting takes a confirmation and stops automated entries, because the bot's KILL_SWITCH guardrail reads the same flag. While halted, a red banner runs across the top of the app, even if the halt came from another device. Resuming takes its own confirmation.
          • Observe-onlyOne switch puts the bot in observe-only mode: it keeps writing signals and places no orders.
          • AI Trades and PerformanceA view of what the LLM trader did, and a P&L performance view.
          • Locked downProtected API routes refuse anyone without a PIN session. If the PIN isn't configured, they refuse everyone instead of opening. The public health check answers only {"ok": true}.

          The dashboard shows live account figures, so it stays private and isn't linked here.

          Incidents

          Four things that broke, and what changed

          Three of these are the system saying it was fine when it wasn't. Dates and numbers come from the repo: the incident docs, the commit messages, and the comments left in the unit files.

          2026-08-05

          Heartbeat green, feed dead

          It said
          heartbeat every 60 s, no alerts
          It was
          no market data from 07:58 on. A full session, zero trades.

          The same broker username logged in somewhere else. The broker allows one market-data session per username, so all 27 of the bot's subscriptions were refused in one burst (Error 10197). Those errors arrive on an async event, after the subscribe call has already returned, and nothing retried. The stale-feed detector built after an earlier outage in July did not catch it.

          Changed
          • The feed listens for async errors and keeps a set of subscriptions it expects to be alive.
          • Stale subscriptions are re-subscribed instead of trusted.
          • The heartbeat carries a FEED=DEAD state and repeats the alert.
          • 13 tests, grouped by the four parts of the fix.
          2026-08-14

          "Deployed" printed over a crash loop

          It said
          ✓ moneyloop deployed
          It was
          dead for 22 hours. 7,581 restarts. No alert.

          The deploy shipped a file that imported a module sitting uncommitted in my working tree. The service died on import and systemd restarted it every 10 seconds. With Restart=always and RestartSec=10, the default limit of 5 starts in 10 seconds can never trip, so the unit never becomes failed and OnFailure never fires. The deploy script ended in systemctl is-active || true, which swallowed "activating".

          Changed
          • Deploy imports the package from a throwaway worktree at HEAD before it pushes. Untracked files can't be there.
          • The verdict needs the literal word "active" and an unchanged restart counter.
          • Units get 5 starts per 300 seconds and an OnFailure pager.
          • OnFailure lives in [Unit]. systemd silently ignores it in [Service].
          2026-09-03

          The health check that told strangers too much

          It said
          {"ibkr_connected": true, "market_data_syms": [...]} to anyone who asked
          Needed
          a status code for the deploy poll

          The health route sits outside auth so the deploy poll can reach it. It was also telling the whole internet whether the broker link was up and which symbols the account subscribed to. That is the shape of the book, and the times it is weakest.

          Changed
          • Strangers get {"ok": true}. Diagnostics need an operator session.
          • Three days later auth was made to fail closed: with no secret configured, every protected route returns 503 instead of opening.
          2026-09-27

          The backup that stamped itself fresh

          It said
          freshness stamp written
          It was
          an incomplete copy

          The journal and state exist in one copy on one server, so a nightly job pulls them to another machine. One leg of that pull treated every non-zero exit as "that folder isn't there yet" and wrote the stamp anyway. The installed job had also drifted: it was four days behind the repo, still on the version without the retry loop.

          Changed
          • Absence is probed explicitly. A real failure retries, then aborts before the stamp.
          • The installed job was reinstalled from the file in the repo.
          • Every run ends by verifying the copy it just made.
          Coding agents

          Agents wrote most of this. Here is what keeps that safe.

          705 of the repo's 987 commits carry an agent as co-author. I say what gets built, review it, and decide what merges and what deploys. The rules below are in the repo's instruction file. Each one is there because something went wrong first.

          • Claim disciplineadded 2026-08-30

            Below 30 decided samples, no verdict words. Every number ships with its n in the same sentence. A finding needs two independent cuts that agree. When an earlier claim flips, the message opens with the reconciliation.

            Why: a month of confident verdicts about strategies that later reversed.

          • Smallest version firstadded 2026-08-31

            Ship the minimum that answers the question asked, and say in one line what was left out.

            Why: I asked where the nightly learning goes. The answer was one section of stats. What came back was an all-time cut, a promotion rule, a sidecar file and 118 lines of tests, one of them for a failure the system cannot produce.

          • Pin the goaladded 2026-08-30

            Every task starts with a one-line goal. One detour is free. A detour off a detour needs my OK. Done means the original question got answered.

            Why: long sessions that ended somewhere else, with nothing committed and the first question still open.

          • Nothing ships without mestanding

            Agents work on branches. Merges to main, deploys and server config changes happen only on my explicit approval. Uncommitted work is mine to discard, never theirs.

            Why: two real incidents, a reverted strategy file and an overwritten instruction file.

          • Review protocol for order codestanding since 2026-07-15

            One reviewable commit per critical fix. Audits are committed files, never chat. Broker and order-state code counts as reviewed only after failure injection.

          • No broad searchesadded 2026-09-27

            A hook blocks agents from searching the whole tree and routes them to eleven navigation docs instead. It binds Claude, Codex and Qwen alike.

          The release gate

          Every deploy runs six stages inside a throwaway worktree checked out at the exact commit about to ship. The tree that is tested is the commit that is deployed. No stage needs the broker, the database, the network or a secret.

          1. 1/6MoneyLoop unit and production-config suites
          2. 2/6API suite: auth decisions, halt scope, order routes
          3. 3/6Environment and snapshot compatibility
          4. 4/6Python lint for syntax and undefined names
          5. 5/6Frontend lint for undefined identifiers
          6. 6/6Frontend build

          Findings get worked, not filed

          On Sep 1 a reviewer agent went through a seven-branch data stack before it ran against a real database. It returned seven findings: three high, three medium, one low. The two strongest were not logic bugs. One was a liveness backstop the docs relied on that did not exist anywhere in the repo.

          Six were fixed in code, tests or units before the next stage started. The low one was accepted as flagged, which was the reviewer's own recommendation.

          A deploy journal is generated automatically: 52 daily entries since Jul 31.
